## Evidence model

This folder is a **baseline evidence event**, not a one-time pass/fail quiz. Each subskill is interpreted separately:

- iteration/control flow
- callback and return semantics
- `some` / `every`
- `reduce` / `reduceRight`
- search operations
- `map` / `filter` and method selection
- sparse-array behavior

A correct cold implementation is production evidence. A correct explanation is conceptual evidence. Neither automatically proves transfer or delayed retention.

## After the push

The cold commit is permanent evidence. Diagnose each subskill independently. Preserve demonstrated strengths; remediate only demonstrated weaknesses using the exact entries in `resources.md`.

An immediate repair can verify remediation, but it does **not** establish retention. Successful repairs should reappear later in a different context as a transfer/retention challenge. High-frequency array operations remain active branches and should recur later with more ambiguity, composition, and realistic data rather than beginner repetition.
